# 观盘 Next 私人顾问并行版本

此包用于与现有观盘服务并行部署。新 Compose 项目名为 `guanpan-advisor`，容器监听和 NAS 映射端口均为 `8789`，数据卷为 `guanpan_advisor_data`。旧服务 `30001`、旧项目和旧卷不受影响。

## 部署

1. 在 NAS 上新建独立目录，把完整源码包解压进去。不要覆盖旧版目录。
2. 确认端口 `8789` 可用，在 `.env` 中设置 NAS 上已经配置的 DeepSeek 参数。保持 `.env` 权限私有，不把密钥填入 iOS 或网页。新服务端口变量名为 `GUANPAN_ADVISOR_PORT`，默认 8789，与旧服务的 `GUANPAN_PORT` 独立。
3. 在新目录运行（服务代码构建进独立镜像，不挂载旧版宿主机源码目录）：

   ```sh
   docker compose -p guanpan-advisor up -d --build
   docker compose -p guanpan-advisor ps
   docker compose -p guanpan-advisor logs --tail=100
   ```

4. 打开 `http://NAS内网地址:8789/health`，确认 `codeVersion` 为本包版本。网页是 `http://NAS内网地址:8789/`。
5. 新库是空库。iOS 设置只保存一个 NAS 地址；要使用新库，将地址改到 8789，然后由用户主动下载/上传并核对账本。切回旧库时改回 30001。不要将两个库当成自动同步或自动合并的副本。

`update.sh` 只会重建当前目录内名字严格为 `guanpan-advisor` 的 Compose 项目，不会搜索、停止或覆盖其它 Guanpan 容器。升级请先备份 `guanpan_advisor_data`。

## 顾问能力

- `/v1/advisor/inventory` 统计真实持仓分时档案的采集覆盖情况。
- iOS 私人顾问页中的「授权 AI 综合分析与交易方案」经二次确认后读取真实持仓、NAS 行情、历史分时和新闻标题，调用 NAS DeepSeek。
- 本地规则只把行情/覆盖/交易规则门槛都满足的标的分类为网格候选、T+0 做 T 候选或暂不交易。价格是条件限价参考，只有提供足够数据、已核验交易规则、可用资金和可卖份额时才会附带份额与假设成交下的净收益/等效降本估算。
- 使用 Google News RSS 搜索新闻标题，展示来源、日期和链接；聚合标题不视作已核实新闻。RSS 或 NAS 出网失败会显示缺口。在线 AI 不替代本地交易数据门槛，也不会提交订单。
- 分时数据从服务实际运行后的采集开始累积，不会补造旧历史。默认最低筛选为 60 个有效交易日、每日至少 200 个有效分钟点。达到筛选标准不构成收益保证。

## 未完成/部署前需知

- 服务没有应用登录认证，只能放在受信任 LAN/VPN；不要直接暴露公网。
- NAS 本身需允许访问行情源、Google News RSS 和 DeepSeek。各外部源可不可达需要部署环境联调验证。
- 交易规则使用 iOS 保存且带来源、核验时间的证券规则；未核实规则、未知 T+0/T+1、缺少行情或可卖份额时不生成具体方案。费用输入按已核验规则计算，仍未计入价差、滑点、潜在税费和成交失败。
- 本地策略是透明的历史筛选启发式，不是经验证的预测模型。任何限价参考都不是券商订单。
- iOS Xcode 编译、模拟器、真机、NAS 并行部署和网页浏览器联调尚未确认成功；先在隔离环境测试，再决定是否使用新地址。
